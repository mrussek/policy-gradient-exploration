Deep Deterministic Policy Gradient

An interactive visual guide to continuous-action reinforcement learning

Why DDPG?

Most reinforcement learning algorithms — like DQN or REINFORCE — work with discrete actions: move left, move right, jump. But many real-world control problems have continuous action spaces: how much torque to apply, what angle to steer, how hard to accelerate.

You can't just enumerate every possible torque value and pick the best one. DDPG (Lillicrap et al., 2015) solves this by combining two ideas: deterministic policy gradients and deep Q-learning, producing an actor-critic algorithm purpose-built for continuous control.

Key idea: Instead of outputting probabilities over actions, the policy network directly outputs the action value — a real number (or vector). A separate critic network learns to evaluate how good that action is.

Actor-Critic Intuition

Think of the actor as a student and the critic as a teacher. The student proposes an action; the teacher grades it. Over time the student learns to propose better actions, and the teacher gets better at grading.

Experience Replay

DDPG stores every transition (s, a, r, s') in a replay buffer. During training, it samples random mini-batches — this breaks correlation between consecutive samples and lets each experience be reused many times.

Buffer empty

Soft Target Updates

DQN copies weights to the target network every N steps (a hard update). DDPG uses a soft update — blending a tiny fraction τ of the online weights into the target at every step:

θ' ← τθ + (1 − τ)θ'

The slider below lets you see how different τ values affect how quickly the target tracks the online network. Typical values are τ ≈ 0.005.

Exploration Noise

Because the policy is deterministic, it would always take the same action in the same state — no exploration! DDPG adds noise to the action during training. The original paper uses Ornstein-Uhlenbeck noise (temporally correlated), though simple Gaussian noise often works too.

Notice how OU noise has momentum — it tends to continue in the same direction — while Gaussian noise is independent at each step. OU can be better for physical control tasks where jerky exploration is undesirable.

The Full Algorithm

Here's DDPG step by step. Click each phase to see it animated below:

1
Observe state s from the environment
2
Select action a = μ(s) + noise using actor + exploration noise
3
Execute action, observe reward r and next state s'
4
Store transition (s, a, r, s') in replay buffer
5
Sample mini-batch from replay buffer
6
Update critic: minimize (Q(s,a) − (r + γQ'(s', μ'(s'))))²
7
Update actor: maximize Q(s, μ(s)) via ∇aQ · ∇θμ
8
Soft-update target networks: θ' ← τθ + (1−τ)θ'

DDPG vs Other Algorithms

DQN REINFORCE DDPG TD3 / SAC
Action space Discrete Discrete / Cont. Continuous Continuous
Policy type Implicit (argmax Q) Stochastic Deterministic Deterministic / Stoch.
Replay buffer Yes No Yes Yes
Off-policy Yes No Yes Yes
Target networks Hard update None Soft update (τ) Soft update (τ)
Exploration ε-greedy Policy entropy Action noise (OU/Gauss) Noise / entropy bonus

TD3 (Twin Delayed DDPG) and SAC (Soft Actor-Critic) are successors that fix DDPG's overestimation and brittleness issues — but DDPG remains the conceptual foundation for modern continuous-control RL.

Key Takeaways

  1. DDPG extends DQN-style value learning to continuous actions by pairing a deterministic actor with a Q-value critic.
  2. The actor is trained by following the critic's gradient: push the action in whatever direction increases Q.
  3. The critic is trained with Bellman error, using target networks for stability.
  4. Soft target updates (τ blending) prevent the oscillations that hard copies would cause.
  5. Replay buffers decorrelate samples and improve data efficiency.
  6. Exploration noise (OU or Gaussian) is essential because the policy is deterministic.
